# 拾题成卷 开发与验收流程 V1

2026-11-04 · V1 审核修订，已补齐规则用例与阶段状态，供后续开发 agent 接手

**按能验收的小阶段推进。每阶段先明确通过条件，先用测试固定关键规则，再实现、跑回归、交出可试用的结果。** 这份文件在用户启动开发后生效。当前处于需求确认阶段。

开发需求先建 GitHub Issue，分支和 PR 关联 Issue。验收结果逐条回填，必需项通过后再关闭。仓库公开范围、必要测试文档和 AI 密钥处理按[GitHub 协作与开源发布方案](GitHub协作与开源发布方案.md)执行。

## 1. 谁负责什么

| 角色 | 责任 |
|---|---|
| 用户 | 定目标、范围和验收标准。审核小学语文、小学数学、初中语文和初中数学样题，判断拆题、标签、答案、材料与印出来的效果。确认需要的产品取舍。 |
| 开发 agent | 将需求拆成阶段任务，选实现方法、写代码和测试、定位和修复问题，维护可运行安装包、测试证据和交接记录。使用临时题库验证，学科问题提交具体题号和原卷页让用户判断。 |
| 阶段复核 | 按需求编号对照检查。开发 agent 先自测。涉及学科内容和纸面效果的关口由用户验收。平台实测、自动化结果与用户验收分别记状态。 |

需求先读 [产品需求文档](产品需求文档-V1.md)，技术参考读 [本地跨平台应用方案](本地跨平台应用方案-V1.md)，样题回查 [原卷与题库对照研究](原卷与题库对照研究.md) 和 [PDF 清单](../research/PDF清单.md)。

## 2. 开发顺序

| 阶段 | 需求 | 可交付的结果 | 过关条件 |
|---|---|---|---|
| M0 跨平台、编辑打印和 AI 输入验证 | REQ-01 的编辑保存、REQ-07、REQ-05 的打印链路、REQ-02 的模型输入 | 最小桌面安装版、实际编辑生成的样卷、文字与裁图草稿记录、依赖版本与使用规模记录 | macOS、Windows 能安装并断网启动。从界面输入中文、修改公式、插图和表格，保存重开后导出，不用预置 HTML 代替编辑验证。确认两端最终 PDF 的打印入口，实打样页。两种 AI 输入分别返回可校对草稿；固定版本、格式范围和量化目标。 |
| M1 用样题组卷 | REQ-03、REQ-04、REQ-05 | 用原卷校对的样题、筛选、题篮、学生卷与教师版、定稿重印 | 先用一组阅读题和一道带图数学题跑通筛题到打印，再补齐样题表。回归覆盖选答总分、依赖与重编号引用、卷内改分、版本重审、学生卷内容隔离、双 PDF 中断和历史重印。 |
| M2 原卷录题与旧库迁入 | REQ-01、REQ-03、REQ-06 的迁入 | 原卷双栏工作台、人工录题和审核、Tiku 与 mathVault 小批迁入 | 从新 PDF 录入一道带图题并进入新卷。旧库默认待核，完全重复不新增；来源变化、目标已修改时可看差异并决定，不静默覆盖。用户抽核原题、图、公式和标签。 |
| M3 AI 草稿和复核 | REQ-02、REQ-03 | 文字与扫描裁图入口、草稿校对和逐题采纳、调用失败后的手录路径 | 自动测试覆盖异常、取消后迟到、重复响应、超限和审核门槛。真实调用覆盖两种输入。用户从首批四个学科范围抽核，记录修正项及从选区到采纳的总耗时，与人工录题比较。 |
| M4 本地日用版验收 | REQ-01 至 REQ-07 | 两平台安装包、已核样卷、备份恢复和简明使用说明 | 两平台断网跑完整人工流程，分别验证备份与恢复，至少做一次跨平台恢复；补齐中断恢复、输入安全和规模测试。用上一个可运行测试版的数据验证升级。用户复核实际打印，全部必需验收项有通过证据。 |

M0 用隔离题库。固定响应可验证 AI 草稿结构，真实模型路径和费用按当次授权确认。复审用文本提取工具检查了已下载的 19 个 PDF，全部未提取到正文。本地南充九年级语文卷第 3–4 页可提取正文。M0 用这两页测试文字路径，用东城 2024–2025 上期末数学卷第 7 页第 29 题测试裁图路径，选区包含设问、车票图和手续费表。样本定位见[对照研究](原卷与题库对照研究.md)。

M0 另建可复核的基线记录：系统与架构、CPU 和内存、Electron 及内置 Node、数据库驱动、编辑器与其他关键依赖版本；记录实际支持的格式、A4 边距与缩放、题库题量、原卷页数与文件大小、单卷题数、AI 单次文字量与裁图数量和大小。为启动、检索、保存、导出、备份写出具体耗时上限及测量步骤，测量前固定目标，目标与实测分列。未确定这些值不能关闭 M0；M4 在约定规模下复测，不用少量样题代替规模验证。

本阶段的程序检查和相关回归通过后，agent 可继续开发不依赖待验结论的任务，交接中写明继续范围。学科和纸样结果按下述节点集中复核。缺 Windows 实测环境或模型调用条件时，分别标明待验项目、原因和补验方式。平台和模型验收仍是日用版交付条件。M0 向用户交编辑生成的样卷，M2 与 M3 集中交样题和审核记录，M4 做最终试用。

每条验收分别记录程序检查、macOS 实测、Windows 实测、学科复核和纸样复核。单项用“未执行、通过、失败、待补验”；不适用必须写理由。阶段汇总用“未开始、进行中、部分完成／待补验、已完成”。只有本阶段必需项全部通过且无阻断缺陷才标已完成；自动化通过不能替代平台或人工验收，继续开发也不代表前一阶段已关闭。

## 3. 每个阶段怎么做

1. **定小任务。** 为任务写上对应的需求编号、用户操作、样本、预期结果，以及可能失败时的表现。先检查已有代码和测试，复现现状。关键需求有歧义时带着具体例子请用户定，常规实现由 agent 判断。
2. **先写会失败的测试。** 业务规则先把期望变成能执行的检查，确认失败来自功能缺失或真实缺陷。例子是两篇习作选一，加入题篮后该组只计 30 分。遇到界面排版或设备兼容，先写复现步骤与通过标准，保留对照截图或样卷。
3. **做最小实现并复跑。** 先让本次测试通过，再跑相关回归和类型检查。补齐取消、失败、重复导入和退出重开等路径。运行需要写入的测试时使用隔离的数据目录和测试库。
4. **检查真实产物。** 每个阶段至少从用户正常入口走一遍。涉及安装、系统对话框和打印的任务用安装包验收；对题目内容，核对实际原卷和打印稿。自动化可以测到文件生成、题号和总分，印出来的效果仍要人工看。
5. **记录并交接。** 给出需求编号、可复现步骤、使用的样本、通过与失败的检查、安装包或样卷路径，以及哪些项需要用户验收。优先修复题意或答案错误、数据丢失、重复入库、学生卷泄露答案、打印失败和启动失败；涉及本阶段通过条件的缺陷修好并回归后再关阶段。

## 4. 测试安排

| 测试层 | 用来检查 | 首批必须覆盖 |
|---|---|---|
| 单元测试 | 无需打开 App 的业务规则 | 题组依赖、二选一计分、重编号及内部引用、改分后的评分适用状态、版本重审、同组材料去重、答案和题号对齐、AI 响应结构校验。 |
| 集成测试 | 真实临时数据库、文件和导出 | 迁入冲突与重试、保存失败回滚、强制退出后恢复、升级前后数据一致、备份期间暂停写入、恢复失败后原库可用、AI 超时或迟到后保留人工草稿、双 PDF 部分失败后原定稿可用。 |
| 界面端到端测试 | 从正常界面完成操作 | 打开 PDF、编辑并审核、筛题、组卷、导出、退出重开。优先自动化稳定路径，原生文件和打印对话框留可复现的人工步骤。 |
| 安装包与纸样测试 | 两平台的实际运行和打印 | 干净环境双击、断网、中文路径、跨机恢复、实际输出学生卷和答案卷。抽查缺页、裁切、留白、公式、题号和分值。 |
| 学科复核 | 题意、标签、答案与评分能否用于教学 | 以用户审核的题为验收样本。记录原卷位置、修改理由和复核人。学科判断与程序测试分别记结果。 |

启动开发后固定可重复运行的检查入口，至少覆盖类型检查、单元与集成测试、安装包基本检查。Electron 的界面测试工具在 M0 小范围验证，选定后固定依赖版本和测试命令。实际模型调用另留验收记录，自动化测试用固定响应覆盖正常及失败场景。[Electron 自动化测试指南](https://www.electronjs.org/docs/latest/tutorial/automated-testing)

以下用例补充各 REQ 原有验收，不替代原有样题、AI 异常和跨平台检查。它们是待实现的通过标准，当前没有执行结果。开发时为每个编号补上具体步骤、预期、实测、版本和证据路径。

| 编号／阶段 | 需求 | 操作与通过标准 |
|---|---|---|
| ACC-01／M0，M2 回归 | REQ-01、03、05 | 从界面输入中文、修改公式、插图和基础表格，保存重开后导出。内容完整，格式符合支持范围；不支持的格式明确提示，不静默丢失。 |
| ACC-02／M1 | REQ-03、04、05 | 江西数学第 23 题的第（3）（4）问重排为第（1）（2）问，带齐共用条件与必要图，题干及答案引用对应正确。缺依赖、依赖成环或引用未核时阻止定稿；人工确认后再改相关编号，要求重新核对。 |
| ACC-03／M1 | REQ-03、04 | 从依赖前问的小问出发改写前提，生成待核修订版，审核前不能定稿；默认路径保留所需前问或整组，不擅自改题。 |
| ACC-04／M1 | REQ-03、05 | 将 Tiku 的 Q2020-NCZK-011 从 6 分改为 4 分。学生卷无冲突旧分值，教师卷不把原 6 分细则作为本卷评分；分别验证确认新评分和标评分待补两条路径，题库原分值和原评分不变。 |
| ACC-05／M1 | REQ-03、05 | 一份材料被三道题引用，修改后列出受影响题；采用新版的题回待核，草稿不自动切换。旧定稿 PDF 的校验值不变，重印仍用原文件。前问版本变化另测一次。 |
| ACC-06／M2 | REQ-06 | 迁入已知偏差的 mathVault 第 25 题，旧“已入库”不变成新“已审核”。分别测试完全重复、来源修正和目标已人工修改；保留来源编号与处理记录，不重复、不静默覆盖。 |
| ACC-07／M1，M2 回归 | REQ-01、05 | 在附件写入后数据库提交前、第二份 PDF 生成中、定稿提交前后分别强制退出。重开后仅完整提交的数据标已完成，其余可重试；旧数据可用，同一提交重试不产生两套定稿。 |
| ACC-08／M4 | REQ-06 | 备份期间尝试编辑和后台写入，暂停并提示；完成、失败和取消均解除暂停。恢复备份后核对数据库、原卷、图片与历史 PDF 的引用和校验值一致。 |
| ACC-09／M4 | REQ-06、07 | 分别用缺附件、校验值不符、越界路径和不支持版本的备份恢复；另在活动题库切换前后强制退出。失败或未完成切换时原库可打开，成功切换时新库完整；两平台恢复及至少一次跨平台恢复留记录。 |
| ACC-10／M0 初测，M1、M4 回归 | REQ-05、07 | 核对最终双 PDF 与实际纸样的 A4、边距、缩放、长材料分页、公式、表格和图。超大图表须提示，学生卷无答案及答案图；预览后改编排必须重新生成，打印使用确认的文件。 |
| ACC-11／M0 初测，M3、M4 回归 | REQ-02、07 | 在粘贴内容、旧库与 AI 固定响应中放入脚本、远程图片和越界附件引用；确认未执行脚本、未自动联网或读取无关文件。检查越权进程调用被拒，模型密钥不出现在题目、日志或备份。 |
| ACC-12／M0 定目标，M3、M4 验证 | REQ-01、02、04、05、06、07 | 按 M0 固定机器、规模和步骤测启动、检索、保存、导出与备份；实测符合约定上限。AI 输入超限时提交前提示，草稿保留。记录相近难度样题的人工录入耗时与 AI 选区、等待、校对、采纳总耗时及修订量，不由少量样本推断普遍提效。 |

AI 输入确认、草稿校验、人工审核门槛及取消与重复处理是通过条件；省时效果另记观察结果。未观察到省时应如实交接并调整入口或使用说明，不能写成已验证提效。若改变首版功能范围，按需求变更处理。

## 5. 首批样题与预期

题号和 PDF 页在[对照研究](原卷与题库对照研究.md)中可查。用原卷、答案和评分文件建立已核对的测试样本，预期结果经人确认。实际测试夹具和业务数据目录分开。首轮重点是前五行涉及的四个学科范围，后三行补查结构能否通用。

| 样本 | 验收点 |
|---|---|
| 小学语文质量监测卷第 15(3) 题 | 一份留言条，格式、内容、表达分三项，总分 5。 |
| 同卷第 17 题 | 两篇习作选一，卷面呈现两个候选，总分只计 30。 |
| 东城六年级数学第 26 题，2025–2026 上 | 一张作答图可容纳组合图形和对称轴两个评分点。 |
| 南充九年级上期语文第 8–11 题 | 比较阅读的多份材料完整，题号重排后仍能找到两句翻译与评分点。 |
| 江西初中数学第 23 题第 (4) 问 | 依赖第 (3) 问的情境，缺前提时不得定稿；学生卷与答案用图区分。 |
| 江西初中英语第 78–82 题 | 五个作答位置共享一组选项，选项表随题组打印。 |
| 江西初中物理第 20(4) 题 | 教师版保留指定的两空可交换顺序。 |
| 江西初中化学第 18(2) 题 | 一个小问同时有方程式和装置选择，答案与两个位置分别对齐。 |

旧库迁入另以 mathVault 2023 南充中考数学第 25 题验证校勘。题意缺失的旧记录应进入待核，保留旧编号，校对原卷后再转为可出卷。扫描卷和文字卷分别测试一次录入。

## 6. 给下一位 agent 的交接要求

- 接手先读项目说明、需求、技术方案和本文。检查当前代码与已有改动。按阶段开始，首个开发任务是 **M0 跨平台安装、编辑打印与 AI 输入验证**。
- 每个阶段保留一条可复核记录。至少包含阶段编号、关联 REQ 与 ACC 编号、版本、系统与架构、样本、预期与实测、证据路径和待补验原因。按第 2 节分别记录程序、平台、学科及纸样状态，不以单一“测试通过”代替。
- 用户反馈先变成可重现的例子。若改动产品范围、学科规则、AI 处理范围或旧库兼容方式，更新对应需求和验收案例后再实现。日常工程选择记录在交接，不反复让用户决定技术细节。
- 真实题库、用户原件和外部发布与开发测试分开处理。AI 联调使用确认过的样本；涉及付费、上传未授权材料或发布安装包，按当次授权执行。

**交付检查**。从新原卷录入并审核一道题，能筛到它、选进卷、生成并预览双份 PDF、定稿、打印，再关掉 App 重开并重印。两平台都实测，备份可恢复，原有验收及 ACC-01 至 ACC-12 的必需检查全部通过，相关题目和纸样经用户复核。未完成项带着证据交接，日用版保持待验，不记为已交付。
