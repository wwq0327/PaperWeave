# 原卷录题与旧库迁入设计 V1

2026-11-05 · 对应 M2（REQ-01、REQ-03、REQ-06）

## 1. 目标与边界

M2 解决三件事：把原卷 PDF 登记进题库并去重；在左卷右题的界面里手工录入结构化题目并跨次编辑；把 Tiku 与 mathVault 的既有 Markdown 题按来源指纹迁入，先预览、再决定，不静默覆盖。

不在本阶段：整卷自动 OCR、自动判分、题库删除与合并、备份恢复（M4）。真实旧库数据只在本机由教师选择目录后读取，夹具与测试数据全部自制。

## 2. 数据模型（数据版本 7）

> 版本 6 建考试与原卷表；版本 7 补建 `import_batches`、`import_records`（#47 设计列出但未在 v6 实际创建）。

新增表，不改动已有题目内容 JSON：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `exams` | `id, title, stage, subject, grade, region, exam_type, year, source_name, created_at, updated_at` | 一场考试／一份卷。学段、学科、年级必填；地区、来源允许空串表示待补。 |
| `exam_sections` | `id, exam_id, title, subject, position` | 卷内分部。合卷的不同分部可各标学科；`subject` 为空串时沿用考试学科。 |
| `original_files` | `id, sha256 UNIQUE, relative_path, original_name, size, created_at` | 原件。路径固定为 `originals/<sha256><ext>`，相对用户数据目录。 |
| `exam_originals` | `exam_id, file_id, role, created_at`，主键 `(exam_id, file_id, role)` | 角色：`paper` 原卷、`answer` 答案、`rubric` 评分细则、`answer_sheet` 答题卡。原卷每场一份；其他角色可多份。 |
| `question_exams` | `question_id, exam_id, section_id, created_at`，主键 `(question_id, exam_id)` | 题目身份与原卷的关联；题目版本仍各自保存 `source.section/pdfPage/originalNumber`。 |
| `import_batches` | `id, kind, root, created_at, summary` | 一次旧库扫描／导入的批次；`summary` 为 JSON 计数。 |
| `import_records` | `id, batch_id, kind, source_key, source_hash, target_question_id, target_version_id, decision, detail, updated_at`，唯一 `(kind, source_key)` | 每个旧库来源的最新处理状态与来源快照摘要。 |

`SourcePosition` 不改字段。页码与题号继续由题目内容保存；原卷文件通过 `question_exams` 找到。旧题没有页码时先记为第 1 页并在导入预览标「页码待补」，教师审核时改正。

## 3. 文件存储与去重

- 导入时主进程打开文件对话框，只接受 PDF；读取上限 100 MiB，校验 `%PDF-` 文件头。
- 计算 SHA-256；若 `original_files` 已有该指纹：
  - 已有考试以 `paper` 角色挂接该文件时，直接返回该考试，标记 `existing: true`，不再复制。
  - 没有考试挂接时（异常残留）创建考试并挂接，不复制第二份。
- 新文件先写入 `originals/.tmp-<uuid>`，校验后原子改名为 `originals/<sha>.pdf`，再写数据库；数据库失败时只删除本次新建的临时／目标文件。
- 读取原卷前检查路径必须位于 `originals/` 内、是普通文件、大小与记录一致、SHA-256 与记录一致；任何一项不符都报错，不返回字节。
- 附答案、评分细则、答题卡复用同一文件池；同一考试同一角色可挂多份。原卷角色若已存在，拒绝静默替换，需先由后续 Issue 提供解绑流程。

## 4. 双栏录题

- 工作台从考试进入，左栏显示该考试的 `paper` 文件；右栏编辑一道题的草稿。
- 左栏使用 PDF.js 渲染当前页；支持上一页／下一页、页码直达和 1×—3× 缩放；在页面上拖选区域后裁为 PNG，按哈希存入附件目录，插入当前编辑目标的图片块。
- 题目编辑沿用 `QuestionContent`：题组指令、小问、选项、材料、答案、解析、评分点、原分值、依赖小问。分类写到题目身份；来源写 `section/pdfPage/originalNumber`。
- 保存分两种：
  - 「保存草稿」：新建题目且内容状态 `draft`，或对已有草稿调用 `saveQuestionVersion`。
  - 「提交待核」：内容状态 `pending`；答案有内容时答案状态 `pending`，否则保持 `missing`。
- 已审核题再次编辑时使用 `saveQuestionVersion`，新版本回到 `pending`（沿用 #28 的 `savedStatuses` 规则），旧版本保持可查。
- 从考试题单点题目时，切换到其 `source.pdfPage`；找不到原卷文件时给出明确提示，不静默留空。

## 5. 同卷同号重复

保存前按 `exam_id + section_id + originalNumber` 查该考试最新版本：

- 没有重复：正常新建。
- 有重复且当前正在编辑同一题：正常保存新版本。
- 有重复且是新建：返回 `duplicate` 与已有题摘要；界面提供「继续编辑已有题」「建立修订版」「取消」。
  - 继续编辑：载入已有题内容继续修改。
  - 建立修订版：对已有题目身份调用 `saveQuestionVersion`，身份不变、版本加一、状态按规则回落到 `pending`。
- 不同考试或不同分部同号不提示。

## 6. 旧库迁入框架

统一分为「扫描预览」与「执行导入」两步，预览结果必须再次确认才写入。

### 6.1 扫描

输入：来源类型（`tiku` / `mathvault`）与根目录。输出每条：

```ts
{
  sourceKey: string;          // tiku:题目编号 / mathvault:题目编号
  sourceHash: string;         // 题目文件 + 关联材料/图片文件的组合 SHA-256
  status: "importable" | "duplicate" | "changed" | "target_modified" | "blocked";
  title: string;              // 原题号与预览
  section: string; pdfPage: number; originalNumber: string;
  classification: {...};
  preview: string;
  reasons: string[];          // 缺图、失链、待校勘、页码待补等
  target?: { questionId, versionId, version, preview, contentStatus };
  incoming?: QuestionContent; // 仅在可导入/变更时返回
  canRevise: boolean;         // 目标未被人工修改或教师明确允许
}
```

判定顺序：

1. 解析失败、缺必需字段、图片文件缺失、关联材料失链 → `blocked`，不可选。
2. 无 `import_records` → `importable`。
3. 有记录且 `source_hash` 相同 → `duplicate`。
4. 有记录且 `source_hash` 不同：
   - 当前目标最新版本 ≠ 记录中的 `target_version_id`（教师人工改过）→ `target_modified`，默认不允许自动覆盖。
   - 否则 → `changed`，展示来源变化与当前目标内容，允许建立修订版或保留当前。
5. 特殊校勘规则命中 → 在 `reasons` 标「待校勘」，并要求本次显式传 `acknowledgeProofread` 才可导入。

### 6.2 执行

`import:apply(kind, rows)` 每行带来源键、选中的动作：

- `import`：新建题目，内容状态 `pending`，答案状态按有无答案定 `pending`/`missing`；记录 `target_version_id`。旧库「已入库」只写入 `detail.legacyStatus`。
- `revise`：对 `target_question_id` 调用 `saveQuestionVersion`；成功后记录新版本。
- `skip`：记录当前来源指纹与「保留当前」决定，不写题目。
- `blocked` 行不可提交。

整个批次在一个事务内写题目与记录；失败整体回滚。批次汇总写入 `import_batches`。图片来源按哈希写入附件目录，随题目内容引用。

## 7. Tiku 映射

- 扫描 `wiki/by-type/**/Q*.md`；`wiki/passages/**.md` 建立按文件名索引。
- frontmatter 支持标量与字符串列表（缩进 `-` 或内联 `[a, b]`），未知字段保留在 `detail.frontmatter`。
- 题号：`题目编号`，缺失时取文件名 `Q...`；原题号从正文首行 `^\d+[.．]` 提取，缺失时取题号末段数字。
- 分类：学段固定「初中」、学科「语文」、年级默认「九年级」（导入表单可改）；来源取 `来源`，年份取 `年份`，题型取 `题型`，知识点取 `知识点一级/二级` 与 `tags` 去重。
- 正文按 `## 题目正文`、`## 答案`、`## 解析` 分节。第一个 `（1）`／`(1)` 前的文字作题组指令；之后按小问标签拆分。每小问原分值从 `（N分）` 提取，提取不到记 `null`。
- 材料：`关联Passage` 的 wiki 链接按文件名找 passage；passage 正文作材料内容，`passage_title` 作标题。小问 `materialIds` 关联这些材料。材料缺失记 `blocked` 原因。
- 内嵌数学／文本公式按 `$...$` 拆为公式节点；Markdown 图片若有本地文件则导入为附件，缺文件记 `blocked`。
- 旧状态只入 `detail.legacyStatus`；新题默认待核。

## 8. mathVault 映射

- 扫描 `wiki/**/M*.md`，以文件名（不含目录）去重，优先 `by-type` 之外的题型目录，其次 `by-year`；同内容保留一份。
- 分类：`学段/年级/题型/来源/年份`；学科固定「数学」；知识点取 `知识点一级/二级` 与 `核心素养`。
- 正文拆分规则同 Tiku；`配图` 路径相对 `wiki/`，复制为哈希附件并插入题干（当前规则：全部图放在第 1 小问题干末尾，教师导入后调整位置）。
- 原分值缺失时记 `null`，导入预览标「分值待补」。
- **第 25 题校勘规则**：来源键 `mathvault:M2023-NCZK-025` 时检查正文是否同时满足（a）含「直线 KD」排除条件（b）第 (3) 问为探究乘积是否为定值并说明理由。任一不满足即标 `待校勘`，`acknowledgeProofread` 未置位时 `blocked`。导入记录 `detail.proofread = "acknowledged"`。
- 真实数学公式按 `$...$`；保持原文 LaTeX，不自动改写。

## 9. IPC 面

新增通道（全部校验发送方主窗口）：

- `exam:list`、`exam:get`、`exam:import`、`exam:attach`、`exam:fileData`、`exam:questions`。
- `question:createDraft`、`question:saveDraft`、`question:findBySource`、`question:submit`（或复用 `saveQuestionVersion` + 状态接口）。
- `intake:saveFigure`（data URL → 哈希附件）。
- `import:scan`、`import:apply`、`import:history`。

渲染进程不接触文件系统路径，只拿文件标识与字节。

## 10. 失败与恢复

- 文件复制失败、数据库写入失败：原题库不变；不产生半个考试记录。
- 读取原卷失败（缺失、大小或哈希不符）：显示错误与修复办法（重新导入同一 PDF），不显示空白页冒充成功。
- 旧库扫描失败的行逐条列原因；导入批次中一行失败时整体回滚，不留下半批。
- 手工保存失败时编辑内容保留在界面，草稿仍在数据库上一次成功版本。

## 12. 非目标

- 不自动识别 PDF 版面、不自动切题。
- 不迁入 Tiku 的生成物、复习资料与错题记录。
- 不在本阶段实现题目删除、合并、批量编辑。
- 真实 Tiku/mathVault 数据的学科复核由教师完成；自动化只用自制夹具。
