# 拾题成卷 组卷、引用与定稿设计 V1

2026-11-05 · M1 数据模型与界面共同遵循的实现规格

**目标：把已检索的题目组织成可定稿、可打印、可重印的试卷；学生卷与教师卷分别由允许字段生成；卷内编号与引用在重排后正确解析，不靠替换数字。**

本文补足 `产品需求文档-V1.md` REQ-04/REQ-05 中规则层之下的数据结构与判定规则。产品行为冲突时以需求文档为准。

## 0. 范围与边界

- 首版一份自组卷只选一科；题篮为单一当前题篮；不做多卷并行管理。
- M1 只做「题目 → 题篮 → 组卷草稿 → 卷内改分 → 双卷定稿/重印」。原卷登记、旧库迁入属 M2。
- 学生卷只从允许字段生成，不靠 CSS 隐藏；教师卷含答案与可用评分点。
- 卷内改分只作用于本卷，不覆盖题库原分值与评分点。

## 1. 题目模型修订（数据版本 5）

### 1.1 原分值

`SubQuestion` 增加必填字段：

```ts
originalScore: number | null; // 原卷标注分值；null = 未录入
```

- 分值范围 0–1000，允许 0.5 步进（与评分点一致）。
- 原分值是组卷默认分值的唯一来源；`null` 时加入题篮/组卷必须由教师补填，不能静默按 0 计。
- 评分点合计与原分值不一致不拒绝保存，但在组卷时标记「评分细则合计与原分值不一致」，由教师确认后使用。
- `selectionScore` 改为：`originalScore !== null ? originalScore : sum(scoring)`。原分值优先，评分点缺省时才回退。

### 1.2 小问级材料

`SubQuestion` 增加必填字段：

```ts
materialIds: string[]; // 必须出现在 QuestionContent.materials 中；可为空
```

- `QuestionContent.materials` 仍是题组材料池（含版本）。
- 每个小问显式列出自己使用的材料；共享材料由多个小问各自引用同一 `materialId`。
- 校验：小问内去重；每个 `materialId` 必须在题组材料池中存在；题组材料池允许未被任何小问使用（保留给题组指令引用）。
- `selectionDependencies.materialIds` 只返回当前小问的 `materialIds`，不再返回整组材料。
- 出卷就绪检查仍检查题组材料池中所有材料的存在与审核状态；未使用材料的审核要求后续按界面需要收紧。

### 1.3 图片身份与图引用

`Block` 的图片块增加可选字段：

```ts
{ type: "image"; id: string; alt: string; figureId?: string }
```

- `figureId` 在同一题目内容内唯一，格式同其他标识；没有 `figureId` 的图片不能作为图引用目标，但仍可正常渲染。
- 题干、小问、解析、答案中的图引用以 `figureId` 为目标。

### 1.4 结构化引用

题目内容中的文本块支持引用节点；M0 草稿编辑器不产生引用节点，草稿结构不变。

```ts
type ReferenceKind = "subQuestion" | "material" | "figure";

type QuestionInline =
  | Inline
  | { type: "reference"; kind: ReferenceKind; targetId: string; fallback: string };

type QuestionBlock =
  | { type: "paragraph"; runs: QuestionInline[] }
  | { type: "formula"; latex: string }
  | { type: "image"; id: string; alt: string; figureId?: string }
  | { type: "table"; rows: string[][] };
```

- `subQuestion`：`targetId` 为同题组的小问标识。
- `material`：`targetId` 为 `materialId`。
- `figure`：`targetId` 为同题的 `figureId`。
- `fallback` 是引用无法解析时教师可读的文字；不允许为空。
- 校验：目标必须存在；同一题组内同一目标可重复引用；未知 `kind`、未知字段、空 `fallback` 拒绝。
- 卷内解析在组卷/定稿时完成：小问引用 → 卷内小问号（如「(2)」）；材料 → 「材料一」；图 → 「图 2」。解析结果只用于渲染，不改写题库内容。
- 无法可靠解析（目标不在本卷、目标被删除、编号冲突）列入「待核引用」，阻止定稿，直到教师改写 `fallback` 或调整组卷。

## 2. 题篮

### 2.1 表

```sql
CREATE TABLE basket_items (
  id TEXT PRIMARY KEY,
  question_id TEXT NOT NULL REFERENCES questions(id),
  question_version_id TEXT NOT NULL REFERENCES question_versions(id),
  sub_question_ids TEXT NOT NULL,        -- JSON 数组，按题目内容顺序
  primary_sub_question_id TEXT,          -- NULL 表示整题
  position INTEGER NOT NULL,
  created_at TEXT NOT NULL
) STRICT;
CREATE INDEX basket_items_position ON basket_items(position);
```

题篮固定为当前唯一题篮，不建 `baskets` 表；清空题篮即删除全部行。

### 2.2 入篮规则

`basketSelection(content, subQuestionId)` 纯函数返回：

```ts
interface BasketSelection {
  subQuestionIds: string[];       // 需要带入的小问，按原顺序；整题时为全部
  materialIds: string[];          // 当前小问使用的材料
  wholeGroup: boolean;            // 是否必须整组带入
  reasons: string[];              // 直接/传递前问、题组指令、组选答、共享材料
}
```

判定：

- `subQuestionId === null` → 整题全部小问，`wholeGroup: true`。
- 题组指令非空，或组选答 `choose` 且当前小问为候选 → 整组带入。
- 否则带入当前小问 + `selectionDependencies.previous`（直接与传递前问）。
- 共享材料不强制整组；材料在试卷中按 `materialId + versionId` 去重后打印一次。

API：

- `addToBasket(questionId, versionId, subQuestionId, confirmDependencies)`：
  - 校验题目版本存在且属于该题；
  - 未确认依赖时返回依赖报告，由教师确认后再次调用；
  - 已覆盖的小问加入 → 报「已在题篮」，不静默合并；
  - 同一题目版本同一小问集合已存在 → 报「已在题篮」。
- `removeBasketItem(id)`：整体移除该入篮项（含带入的前问），不做部分拆分。
- `listBasket()`：按 `position` 返回题目、版本、小问集合与解析后的依赖摘要。
- `clearBasket()`：清空。

### 2.3 版本快照

题篮保存 `question_version_id`，不随题库新版自动切换。旧版被新版替代时，界面提示可更新；教师确认后才改为新版本并重新检查依赖。

## 3. 组卷草稿

### 3.1 表

```sql
CREATE TABLE papers (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  stage TEXT NOT NULL,
  subject TEXT NOT NULL,
  grade TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
) STRICT;

CREATE TABLE paper_sections (
  id TEXT PRIMARY KEY,
  paper_id TEXT NOT NULL REFERENCES papers(id),
  title TEXT NOT NULL,
  position INTEGER NOT NULL
) STRICT;

CREATE TABLE paper_items (
  id TEXT PRIMARY KEY,
  paper_id TEXT NOT NULL REFERENCES papers(id),
  section_id TEXT NOT NULL REFERENCES paper_sections(id),
  position INTEGER NOT NULL,
  question_id TEXT NOT NULL REFERENCES questions(id),
  question_version_id TEXT NOT NULL REFERENCES question_versions(id),
  sub_question_ids TEXT NOT NULL,       -- JSON 数组
  score REAL NOT NULL,                  -- 卷内分值
  blank_space TEXT NOT NULL CHECK (blank_space IN ('none', 'small', 'medium', 'large')),
  scoring TEXT NOT NULL,                -- JSON（见 3.3）
  score_conflict_confirmations TEXT NOT NULL DEFAULT '[]', -- JSON 数组
  created_at TEXT NOT NULL
) STRICT;
```

- 论文与题目版本绑定；题库新版不自动替换。
- 一份试卷只选一科：创建时固定 `stage/subject/grade`，加入不同学科题目报错。
- 小节按 `position` 排序；题目在小节内按 `position` 排序。

### 3.2 分值

- 加入整题：默认分值 = `selectionScore(content).total`；`conflict` 非空时拒绝加入并提示调整题组或改用可表达题组。
- 加入小问集合：默认分值 = 所选小问 `originalScore` 合计；任一为 `null` 时要求教师补填。
- 卷内分值可改；改后 `score` 与题库原分值分离，题库不变。

### 3.3 评分状态

`scoring` JSON：

```ts
type PaperScoring =
  | { mode: "original" }                              // 分值未改，沿用题库评分点
  | { mode: "adjusted"; points: ScoringPoint[] }      // 本卷调整后的评分点
  | { mode: "answerOnly"; note?: string };            // 只输出参考答案，评分待补
```

- 卷内分值与默认分值相同 → `original`。
- 分值不同且尚未处理 → `needsAdjustment`（独立状态值），定稿阻断，提示「原评分不适用于当前分值，待调整」。
- 教师调整评分点 → `adjusted`；评分点合计必须等于卷内分值，否则阻断。
- 教师确认只输出答案 → `answerOnly`；教师版注明「本卷评分待补」，不打印原评分点。

### 3.4 内嵌旧分值检查

`scoreConflicts(content, subQuestionIds, score)` 扫描题组题干（含题干图片的替代文字）与所选小问的题干、选项、答案、解析及图片替代文字，匹配 `\d+(\.\d+)?\s*分`；若命中值等于题库原分值且不等于卷内分值，列为冲突。题组题干按所选小问原分值与整题默认分值的并集判断，小问内文字按该小问原分值判断。同一位置同值的重复文字合并为一个冲突。教师逐项确认后写入 `paper_items.score_conflict_confirmations`（JSON 数组），未确认阻止定稿。

## 4. 卷内编号与引用解析

### 4.1 编号

- 大题按小节顺序用「一、二、三……」。
- 题目在整卷连续编号 `1..N`；小题用原卷小问号重排为 `(1)(2)…`，不沿用原卷题号。
- 材料按首次出现顺序编号「材料一、材料二……」；图按整卷出现顺序编号「图 1、图 2……」。
- 同一材料在多题复用只编号一次、只打印一次。

### 4.2 解析

`resolvePaperReferences(paperSnapshot)` 返回：

```ts
interface ResolvedReference {
  itemId: string;
  blockPath: string;
  kind: ReferenceKind;
  targetId: string;
  label: string | null;   // null = 无法解析
  reason?: string;
}
```

- 解析使用组卷快照中的题目顺序、小问集合与材料去重结果。
- 无法解析或目标不在本卷 → `label: null`，计入待核；定稿阻断并列出题号与原卷页。
- 题库内容中的 `fallback` 不自动替换；教师必须确认解析结果或改写引用。

## 5. 定稿与重印

```sql
CREATE TABLE paper_finalizations (
  id TEXT PRIMARY KEY,
  paper_id TEXT NOT NULL REFERENCES papers(id),
  student_pdf TEXT NOT NULL,
  teacher_pdf TEXT NOT NULL,
  snapshot TEXT NOT NULL,      -- 冻结的组卷 JSON（题目版本、分值、评分、编号、材料）
  student_sha256 TEXT NOT NULL,
  teacher_sha256 TEXT NOT NULL,
  created_at TEXT NOT NULL
) STRICT;
```

- 定稿前必须通过：科目一致、分值齐全、评分状态不是 `needsAdjustment`、无未确认内嵌分值冲突、无待核引用、就绪检查通过。
- 生成流程分两步：先渲染学生卷与教师卷并写入预览暂存目录（`.paperweave-<id>.preview`），用系统程序打开两份 PDF 供教师检查；教师确认后才复用 `pdf-pair` 原子写入正式目录并插入定稿记录。
- 取消或确认前退出时删除预览暂存，不产生定稿记录与正式目录；启动恢复同时清理未确认预览与未完成暂存。
- 定稿记录不可修改；重印只打开该记录的 PDF，不重新生成。
- 组卷变更后重新预览、重新生成新的定稿记录；旧记录保留。

## 6. 数据版本 5 迁移

- `questions`/`question_versions` 内容 JSON 升级：为每个小问补 `originalScore`（有评分点则取合计，否则 `null`）与 `materialIds`（保守填入题组全部材料 ID）。
- 新增 `basket_items`、`papers`、`paper_sections`、`paper_items`、`paper_finalizations` 表与索引。
- 旧版本内容迁移失败时整次迁移回滚，不留下半升级数据库；更高版本继续拒绝打开。
- 题目内容校验对旧字段缺失给出明确错误，不静默补默认值（迁移负责补一次）。

## 8. 未决项

- 跨题引用（「第 5 题」）暂不建模；M1 只支持同题组内小问、材料、图引用。组卷时若发现跨题文字引用，列入待核由教师改写。
- 答题留白首版用四档枚举，不提供毫米级自定义。
- 多卷并行、跨学科组卷、卷首共用条件不在 M1。
