# 整卷 AI 自动录题开发方案 V2

2026-11-06 · 替代 V1 中“教师逐题确认”的实施部分 · 主任务 [Issue #130](https://github.com/wwq0327/PaperWeave/issues/130)

## 目标

教师选择整份 DOCX / 文字 PDF / 扫描 PDF（可同时选择答案或评分文件），设置一次整卷参数与模型授权范围并启动。此后无需逐题选字、框图、发送、填表或保存，系统自动完成：

1. 整卷识读与版面解析；
2. 题号、小问、选项、题干、作答位置、分值、题型与知识点提取；
3. 共享材料识别、去重和归属到具体小问；
4. 题图定位、自动裁切与回读检查；
5. 同卷答案／评分按题号和小问自动关联；
6. 结构化校验、跨页／跨批合并、异常自动重试；
7. 批量创建待核题目并保存完整来源证据。

教师只处理系统列出的异常项，并对整卷通过项做一次最终确认。**自动录题不等于自动审核入库**：没有来源的答案、分值和解析保持待补，不由 AI 编造；异常未解决前不得批量通过。

- 批量建档已完成（#146 / PR #147）：整卷分类继承、AI 题型与知识点合并、共享材料去重建草稿、重复候选处理、幂等建档、整卷审核与批量确认。

- P0（#153）已完成质量闸门：质量状态与异常码、主进程确认复核、分类继承、材料归属、顶层答案提示。

## 当前关键缺陷（按危险程度）

以下缺陷已由 P0（#153）与 P1（#154）修复；保留原文供追溯，行为以当前代码与测试为准。

1. **低置信度信息在建档时丢失**：`aiQuestionToIntake` 返回 `uncertain` 与新标签，但批量建档只使用表单和材料；审核门槛只检查分类、题干和材料状态，模型写明的“公式待核／图形依赖”不影响批量通过。证据：`src/shared/ai-intake.ts:59-83`、`src/main/whole-paper-intake.ts:64-115`、`src/shared/review.ts:22-35`。
2. **答案可能丢失或部分齐全却整题通过**：顶层 `AiQuestion.answer` 未被 `aiQuestionToIntake` 映射；`answerPresent` 用 `some`，任意小问有答案就整题进入待核，随后可整题批量通过。证据：`src/shared/ai-intake.ts:15-49`、`src/shared/intake.ts:608-610`、`src/renderer/WholePaperPanel.tsx:154-174`。
3. **材料归属过宽**：建档时把材料的全部 `materialId` 挂到所有小问，无法表达材料只属于某组小问。证据：`src/main/whole-paper-intake.ts:206-217`。
4. **批量通过只靠界面**：渲染进程逐题调用状态 setter，主进程只检查状态迁移，不复核最新版本、材料状态、未解决异常或预期版本。证据：`src/renderer/WholePaperPanel.tsx:154-174`、`src/main/question-bank.ts:352-372`。
5. **漏题、重题、半卷成功无系统性阻断**：字符硬切可能截断跨页题；各批独立结果没有合并与覆盖对账；存在失败批、待处理批或空页时仍能对其余题目建档。证据：`src/shared/whole-paper-batches.ts:37-71`、`src/shared/whole-paper-runner.ts:50-80`、`src/main/whole-paper-intake.ts:53-70`。
6. **整卷参数未自动继承**：审核前分类表单仍从空默认值开始，教师需手填全部字段；候选外新标签只暂存于转换结果，建档时未保存。证据：`src/renderer/WholePaperPanel.tsx:14,69,224-232`。
7. **AI 结果契约缺少证据锚点**：只有粗粒度 `page/originalNumber`、字符串 `uncertain`；严格未知字段校验导致新增字段必须同步改协议与测试。证据：`src/shared/ai.ts:44-66,88-108`。

## 质量模型

把“建档结果”和“质量状态”分开，避免把流程成功当成质量通过。

- 建档状态（现有表）：`created / duplicate / failed / skipped / revised`。
- 质量状态（新增）：`auto_passed / needs_attention / resolved / excluded`，附机器可读原因码：
  - `uncertain`：模型自报不确定项；
  - `new_tag`：候选外新标签未确认；
  - `answer_missing`：部分或全部小问没有答案；
  - `score_missing`：原分值缺失；
  - `material_pending`：引用材料未审核；
  - `coverage_gap`：原卷文字未归属或题号不连续；
  - `cross_batch`：跨批／跨页题待合并；
  - `anchor_missing`：来源锚点缺失。
- 整卷审核状态：`processing / needs_attention / ready_for_spotcheck / finalized`。
- 通过门槛由主进程统一执行：最新版本、预期版本一致、无未解决异常、材料已审核、答案状态明确；界面禁用复选框只是提示，不是安全边界。
- 抽检记录：抽样范围、样本版本、结果、时间与最终确认人。

## 技术方案：来源证据链驱动自动录题

### 1. 统一原文中间层

先把三种输入转换为本机可回查的来源单元，而不是直接把整卷文字交给模型：

- DOCX：段落 ID、段落范围、表格、内嵌图关系、公式对象；
- 文字 PDF：页码、文本块、字符范围与坐标；
- 扫描 PDF：页码、页面图像、文字／版面块及归一化坐标。

每个候选题必须携带 `SourceAnchor`（文件、页或段落、字符／对象范围、可选区域坐标、内容哈希）。跨页和跨批合并只依据稳定锚点，不只依赖模型自报题号。现有 `WholePaperFragment` 已含页码与字符偏移，可作为第一版锚点基础。

### 2. AI 负责理解，程序负责约束

- 扩展 AI 协议（同步更新 `isAiDraft` 校验与固定响应）：字段级不确定项、来源锚点、图表引用、材料归属小问、答案来源；保留旧字段兼容。
- 程序建立“原卷覆盖清单”：每段原文必须归入题目、材料、卷首说明、答案或明确忽略项；漏题、重号、重叠归属、跨页断裂均成为可处理异常。
- 模型自报置信度只作提示，不能代替来源锚点、结构校验和裁图回读。

### 3. 分类型自动裁图

- DOCX 优先直接提取内嵌原图，保留段落关系；非 PNG/JPEG 或 OMML 公式先保留对象定位并标待核。
- 文字 PDF 用文字坐标定位题目范围，由授权图像模型返回“题号＋图角色＋归一化矩形”，程序在固定比例页面渲染上裁剪；不优先抽取内嵌位图，避免矢量图丢标注。
- 扫描 PDF 按页发送给现有图像模型，返回归一化区域，本机 Canvas 高分辨率裁剪；坐标只在本机使用，不上传整份 PDF。
- 裁图后做完整性检查，失败时自动扩边或只重跑该页／区域；仍不可靠才进入异常队列。
- 新增依赖仅按需：DOCX 需 ZIP/XML 解析（建议 `jszip` + `mammoth` 或等价方案）；MVP 扫描识读复用现有图像模型，不引入本地 OCR。

### 4. 答案与材料自动关联

- 答案／评分文件单独建立“原题号 + 小问号”索引，自动匹配并保留来源；
- 共享材料只建一次，按 AI 给出的归属关联到具体小问；归属缺失时标 `uncertain`，不静默挂到所有小问；
- 一对多、多对一或缺号时不猜测，自动重试后仍不明确则标待核；
- 无原始答案时不自动生成“正式答案”。如以后增加 AI 参考答案，作为独立、明确标记的功能。

### 5. 自动建档与异常审核

复用现有题目结构、分类、附件、版本和重复检查：所有合格候选自动批量创建为待核题目；同来源重复执行幂等，失败重跑不重复建题，不覆盖已审核版本。

整卷页改为任务摘要与异常队列：总题数、材料数、题图数、答案匹配率、失败项与处理耗时一屏可见。教师无需逐题打开表单，只处理异常，并对通过项一次确认。

## 开发顺序

### P0：质量闸门与异常闭环（先于新格式）

- 持久化 AI 不确定项、新标签、答案／分值缺失、材料待审、覆盖问题；新增质量状态与原因码。
- 修复顶层答案映射与答案完整性判断：逐小问记录缺失，不再“有任意答案即整题可过”。
- 材料建议支持归属小问；归属缺失进入异常。
- 批量通过下沉主进程：复核最新版本、预期版本、材料与异常状态，事务内推进内容／答案状态。
- 整卷参数从考试元数据自动继承，教师只在需要时调整。
- 整卷审核页去掉逐题勾选依赖，改为“自动通过项汇总 + 异常列表 + 一次最终确认”；异常可修正、重跑、排除并留记录。
- 材料集中审核：同一材料只出现一次，可批量提交／通过。

### P1：文字 PDF 全自动闭环 + 黄金样本

- 扩展 AI 协议：来源锚点、图表引用、材料／答案引用、来源覆盖信息。
- 实现跨批题合并、覆盖清单、结构校验与失败自动重跑。
- 用已校对内容建立黄金样本；固定响应只用于程序回归，真实模型另做识读验收。

### P2：DOCX 自动录题

- 保留段落顺序、表格、内嵌图和公式线索。
- 按段落锚点自动拆题并直接提取原图。
- 打通 DOCX 从选择文件到待核题目的无人逐题操作闭环。
- 当前缺少已校对 DOCX 样本，需用户提供后方可做真实验收。

### P3：扫描 PDF、自动裁图与答案关联

- 整页图像识读、混合 PDF 逐页分流、跨页拼接。
- 自动裁图与回读、同卷答案／评分文件自动匹配。
- 失败区域按原页自动重试，不重新上传无关页面。
- 已完成（#156）：PDF.js 仅渲染无文字页，扫描批次走图像模型并返回 `scanAreas`；`nativeImage` 本机裁图后作为小问图片块写入；答案文件独立抽取并按题号／小问唯一匹配；扫描页覆盖率、答案匹配统计与歧义／未匹配异常进入整卷审核与自动确认门槛。固定响应 E2E 覆盖“扫描原卷 + 答案文件”单入口闭环；真实扫描件与真实图像模型仍未验收。

### P4：真实试卷与四学科验收

- 至少各用一份已校对 DOCX、文字 PDF、带图且含跨页题的扫描 PDF。
- 覆盖小学语文、小学数学、初中语文、初中数学。
- 记录模型与费用、自动处理耗时、人工修正次数与耗时、漏题／错切／答案错配，并与同卷手工录题对照。
- 真实模型调用仍按当次授权明确样本、页码、服务和费用范围。

## 样本与授权

- 本机 PDF 样本均已登记在 `research/PDF清单.md`；其中江西物理第 5 页、江西数学第 6 页、东城数学空白版／答案版第 3、7 页可作首批开发对照。

## 验收门槛

- [ ] 三类原卷均只设置一次整卷参数并启动一次，过程中没有逐题选字、框图、发送、填表或保存。
- [ ] 对照原卷核验题数、题号与小问、题干选项、跨页归属、共享材料、题图、答案对应、参数继承和来源定位。
- [ ] 漏题、重号、错配、图文截断和不确定字段全部可见；失败可自动重跑，异常才可人工修正。
- [ ] 合格项自动批量建档为待核题目，通过项一次确认；待核项与异常项不混入正式题库。
- [ ] 相同来源重复执行、失败批次重跑不产生重复记录，不覆盖已审核版本。
- [ ] 固定响应测试与真实模型验收分开报告；真实样本的漏题、错切和答案错配处理完成后才计通过。
