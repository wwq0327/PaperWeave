# 拾题成卷 本地跨平台应用方案 V1

2026-11-04 · V1 审核修订，待 M0 验证

**用 Node.js 做一款离线桌面应用，让教师从已有试卷录题、分科打标签，再从题库选题、组卷和打印。** 建议用 Electron + TypeScript，首轮以 macOS 和 Windows 为交付和验收目标。两端共用应用代码和题库备份格式，分别打包和实测。Linux 留到后续范围评审。

## 1. 首版交付范围

首版给教师本人使用。安装后从应用图标打开，原卷、配图、题库和组卷记录保存在本机，断网也能完成录题、选题、组卷、导出和打印。应用内有四个入口。

| 入口 | 要完成的操作 | 第一版交付 |
|---|---|---|
| 原卷与录题 | 选本地 PDF，确认学段、学科、地区、考试类型、学年和卷名。左侧看卷面，右侧把大题拆成小问，录入文字、图、答案、分值和标签。 | 支持文字 PDF 选字和扫描 PDF 裁图录入，保留原页定位。可以先存草稿，检查后入库。合卷按分部标学科。 |
| 题库 | 从学段、学科、年级、知识点、题型、来源和审核状态筛题，查看原题与答案。 | 按学科维护知识点，题目可挂多个知识点。支持题干搜索，草稿和缺材料的题可查阅，完成核对后才可正式出卷。 |
| 组卷与打印 | 加入题篮，分大题、调顺序、设分值，预览学生卷和教师答案卷。 | 同一次定稿产生两份 A4 PDF，可通过系统打印。支持全卷重编号、总分检查、答题留白、缺材料提示。 |
| 数据管理 | 导入旧题库，备份和恢复，找回历史试卷。 | 小批量迁入 Tiku 和 mathVault。备份包含数据库、原卷、附件和定稿 PDF，可在另一台电脑上恢复。 |

首版以小学语文、小学数学、初中语文和初中数学做学科验收，另用少量其他学科样题核查结构。首版 AI 根据教师选定的文字或少量扫描卷裁图生成拆题和标签草稿，人工审核后入库。整卷 OCR 和自动拆题、自动组卷、在线作答与判分列入后续版本。功能边界以[产品需求文档 V1](产品需求文档-V1.md)为准。

## 2. 录入到打印的工作流程

1. **登记原卷。** 将 PDF 复制进题库目录并计算文件指纹。重复导入提示已有原件。答案卷、评分细则和答题卡作为同一场考试的不同附件关联，保留各自来源。
2. **拆题和标注。** 独立题直接录。阅读、实验、多问计算先建立题组，再拆小问和作答位置。题干、选项、材料、教师答案可以各自引用图片。语文的段落编号、数学公式、地理图例等随对应内容保存。
3. **校对入库。** 从题目能点回原卷页。录入时至少确认学科、原卷位置、设问和必要材料。题意完整且已审核的题可用于学生卷；参考答案或分步评分缺失时，教师确认后出卷，教师答案卷显示待补状态。审核绑定具体内容和依赖版本。
4. **选题和组卷。** 检索可以定位到小问。题篮列出需要带入的共享材料、共用条件、前问或整组，教师确认后加入。同组材料在同组中只印一次。调整题序或删题后重新检查依赖、内部引用和顺序。改编题意或前提需建立修订版并重新审核。首版同分选答组按允许作答的数量计分。
5. **定稿和打印。** 学生卷和答案卷采用同一份编排，编号保持一致。卷内改分后检查内嵌旧分值与评分细则；未调整的细则标待补，不自动缩放。两份 PDF 都生成、校验并经教师预览确认后保存为一套定稿，保留编排快照。后续打印和重印使用原定稿 PDF。

## 3. 数据怎么组织

| 对象 | 首版保留的信息 |
|---|---|
| 原卷与附件 | 考试信息、科目分部、文件角色、来源、文件指纹、本地相对路径。每道题保留 PDF 页码和印刷题号。 |
| 材料与题组 | 稳定编号、版本，按原顺序组织文章、图片、表格和共用指令。保留图号、图片用途、选答规则、卷首共用条件，以及小问到材料或前问的关系与目标版本。 |
| 题目与小问 | 内部编号、版本、题干、选项、作答位置、原分值、标签和审核状态。旧编号留作回查，新卷题号按当前卷生成。 |
| 答案与评分 | 版本、参考答案、可接受写法、评分点、适用分值和出处。允许多空共评、指定空位互换，以及一份作答按多个评分点给分。解析单独保存。首版评分以教师查阅和打印为主。 |
| 新卷与定稿 | 卷标题、分部、题序、卷内分值、本卷评分及确认状态、题目和全部依赖的版本、打印设置和定稿文件。题库原分值与本卷分值分别保存。 |
| 审核与迁入记录 | 审核人、时间、题目及依赖版本；迁入来源库标识、原编号、来源内容指纹、批次、旧审核状态、差异与处理决定。 |

题干建议用受控的富文本结构表达正文、公式、表格和图片引用。学科、知识点、题型、题源分别存储，以便组合筛选。基础标签先用旧库已有分类，导入时人工确认同义标签和知识点映射。

### 3.1 版本、依赖与卷内引用

- 稳定编号标识对象，版本标识一次内容。已审核或被定稿引用的内容不可原地覆盖，修订创建新版本；附件按内容指纹保存，不用同路径覆盖旧图。
- 依赖记录关联具体版本，建立反向索引，修改材料或前问时列出直接和间接受影响题目。采用新依赖的题创建待核版本。组卷草稿固定已选版本，展示更新提示，只有教师选择后才切换；切换后重查审核、依赖与编号。
- 题号、图号和材料号引用存为富文本中的引用节点，保存目标标识，排卷时解析为卷内编号。依赖缺失或成环时阻止定稿。图片内或未结构化的引用保留待核标记，人工确认绑定本次内容与编排；相关内容、顺序或编号再变时，确认失效。
- 原题号与原分值作为来源信息保留，正文中作为标签出现的题号、分值与正式内容分离。不能确定是标签还是题意的一部分时交人工核对，不批量替换数字。卷内评分另存，改分后原评分适用状态失效；新评分须确认与本卷满分及规则相符，未调整时只打印参考答案与评分待补提示。

### 3.2 编辑与排版范围

首版支持段落、常用强调与上下标、行内和独立公式、图片、基础行列表格及结构化引用。公式保存源表达式，图片引用本地附件；不以任意 HTML 作为题目存储格式。M0 选择编辑器并固定具体支持范围，验证中文输入、公式修改、插图、表格编辑、保存重开和导出。复杂格式或不支持的公式须提示，可用清晰裁图或人工改写保留内容，核对后使用。

学生卷与教师卷分别由允许的内容字段生成，不通过隐藏答案元素来实现学生卷。PDF 生成前等待字体、公式和图片完成渲染，缺资源或公式渲染失败时停止定稿。M0 固定 A4、页边距、分页和缩放设置；长表格按行分页，过宽表格或超大图片提示调整。预览打开实际生成的 PDF，确认时核对编排版本未变，并提交同一对文件。系统打印也从定稿 PDF 发起，核查纸型、缩放及实际纸样；不能用另一套 HTML 排版替代定稿文件。[Electron 打印与 PDF API](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions)

## 4. 技术选型

| 部分 | 建议 | 开发前段要验证的事 |
|---|---|---|
| 桌面和界面 | **Electron + Node.js + TypeScript**。界面用 React + Vite。主进程管理本地文件、数据库、窗口和打印，界面通过受控接口请求这些操作。 | 在打包后的应用中验证打开文件、保存文件、退出重开。界面启用隔离，导入的题目内容以受控富文本渲染。[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model) · [安全指南](https://www.electronjs.org/docs/latest/tutorial/security) |
| 本地存储 | **SQLite + 本地文件目录**。数据库存结构化记录，原卷、配图、导出件用相对路径管理。数据库驱动先评估 Electron 内置 Node 所带的 `node:sqlite`，以目标平台安装包实测为准，`better-sqlite3` 作为备选。 | 验证两平台打包后的建库、读写、迁移和备份。使用原生驱动时验证目标架构的模块重建。批量导入、备份等较长操作放后台处理。[Node.js SQLite](https://nodejs.org/api/sqlite.html) · [Electron 原生模块](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules) |
| 读卷与排版 | **PDF.js** 做原卷定位、放大和区域裁图。**KaTeX** 负责公式，前端资源与有授权的字体随应用安装。打印页用 HTML/CSS 排版，由 Electron 生成 PDF。 | 拿中文长文、数学公式、化学式、图表和跨页题组验证。图和短题尽量整体排，长题组允许合理跨页。按 3.2 节验证真实编辑到最终 PDF 的路径及打印一致性。[PDF.js](https://mozilla.github.io/pdf.js/getting_started/) · [KaTeX](https://katex.org/docs/browser.html) · [Electron 打印 API](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions) |
| AI 草稿 | 用独立的模型调用入口接收确认过的文字或裁图，返回待核草稿。调用前显示实际输入，返回后校验数据格式、原卷定位和重复记录。 | 首阶段用一段原卷文字和一题扫描裁图验证模型路径，记录输入范围、响应结果和人工修订量。常规测试用固定响应，密钥与题库备份分开。 |
| 打包 | **Electron Forge**。首批以 macOS Apple Silicon、Windows x64 为验收配置。使用对应系统构建、安装并做打印测试。 | 两边都能在未安装开发工具的电脑上通过图标启动。检查中文路径、系统打印机对话框和备份跨机恢复。对外分发时再定签名和安装包策略。[Forge 打包流程](https://www.electronforge.io/core-concepts/build-lifecycle) |

Tiku 和 mathVault 提供旧题、题号、标签和材料链接。MathForge 提供筛选、题篮与打印流程参考。拾题成卷 用独立的 Node.js 应用承接这些规则。旧库迁入先做预览和重复检查，给出可导入、缺图、失链、待校勘的条目。迁入默认待核，旧状态仅作来源记录。以来源库标识和原编号定位条目，以来源内容及关联材料、附件的指纹判断变化；与上次已处理的来源版本相同则跳过，变化则展示差异，由教师选择建立修订版或保留当前记录，不覆盖目标库的人工修改。每批保留来源快照、处理决定和导入版本，预览后来源或目标变化须重新确认。南充中考数学第 25 题作为首个校勘样本。[本地题库资料盘点](本地题库资料盘点.md) · [原卷与题库对照研究](原卷与题库对照研究.md)

主窗口和 PDF 预览窗口均启用上下文隔离及进程沙箱，关闭页面的 Node.js 集成。预加载层只开放必要接口，主进程校验调用来源、参数和对象权限。附件通过受限协议按标识访问，拒绝越界路径。富文本只接受约定节点，限制导航、弹窗及外部资源加载；AI 返回内容使用相同校验规则。模型密钥由主进程通过系统安全存储管理；配置界面可输入密钥，保存后不回显，不向题目和预览页面提供已保存密钥，也不写入题库、备份或日志。AI 调用只发送确认的输入；远程资源获取另行展示来源并确认。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

M0 记录 Electron 及其内置 Node、数据库驱动、编辑器、PDF.js、KaTeX 和打包测试工具的实际版本，并固定依赖。数据库选择以该 Electron 安装包内的 API 可用性和两平台实测为准，不能用开发机 Node 版本代替。另记录测试机器、数据规模、AI 输入限制和操作耗时目标，目标与实测分别保存。

## 5. 实施顺序与验收

按[开发与验收流程 V1](开发与验收流程-V1.md)推进。依次完成跨平台、编辑打印与模型输入验证，样题组卷，原卷录题和旧库迁入，AI 草稿与审核，日用版验收。每一阶段先写测试或验收步骤，再实现并复测。

数据库事务不能同时提交外部文件，文件操作按下表协调；数据库使用单一写入入口。后台任务也必须遵守写入暂停和恢复切换规则。

| 操作 | 提交与中断处理 |
|---|---|
| 保存题目与附件 | 文件先写入暂存区并校验，移到不可变资源位置后，再用数据库事务提交记录及引用。中途退出不得留下引用缺失文件的已完成记录；尚未引用的文件按操作记录回收或供重试，不删除旧资源。 |
| 生成双 PDF 与定稿 | 为本次编排分配操作标识，暂存并校验两份 PDF，教师预览确认且编排未变后，再提交文件和定稿记录。操作标识防止重试重复提交。重启检查未完成操作：完整且已提交的保留，未提交的恢复为可重试草稿，旧定稿始终保留。 |
| 备份 | 先暂停所有数据写入并等待在途提交结束；生成数据库一致副本，按该副本的引用清单复制原卷、图片和定稿 PDF。清单记录相对路径、大小、校验值、应用与数据格式版本，校验完整后才标备份成功。完成、失败或取消均解除写入暂停。SQLite 快照之外的附件一致性由本流程保证。 |
| 恢复 | 在独立目录解包，检查路径范围、版本支持、数据库完整性及引用文件的校验值；必要迁移只在恢复副本上执行。暂停写入并关闭原库连接后，用可恢复的切换记录更新活动题库位置。启动时遇未完成切换自动返回保留的原库，已完成切换则验证新库可打开。原库保留到新库重开验证成功之后，清理另行处理。 |

首次建库就记录数据格式版本。升级前保存可恢复备份，迁移失败不继续用半迁移的数据；不支持的更新版本备份明确拒绝，不尝试降级读取。原始试卷保存为原件，裁图作为独立附件。[SQLite 备份机制](https://www.sqlite.org/backup.html)

## 6. 当前决策

Node.js、跨平台、本地桌面形态和从录题到纸质输出的工作流程已经明确。Electron、首批平台架构和 A4 双卷是本方案建议。数据库驱动和具体安装包格式由第一阶段的双平台测试确定。现阶段交付方案，开发启动后从 M0 进入。
